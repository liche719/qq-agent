### 读微信视频号（用户 2026-10-20 决定先不做）

纯 HTTP 拿不到：`weixin.qq.com/sph/...` 的 HTML 只有 2.5 KB（SPA 壳），
数据在 `getFeedInfo({generalToken, shortUri})` 后面，而 `generalToken` 只能由微信客户端内的 JSSDK 生成；
视频流还**是加密的**（微信 WASM 生成 Isaac64 PRNG 密钥流，XOR 解密），要 `decode_key`。

真要做，路线是：**旁路小服务**（Python/Node，跑社区实现）负责「链接 → mp4 + decode_key → 解密」，
笨鱼加一个 `readWechatChannel(url)` 调它，拿到 mp4 交给现有 `VideoFrameService` 抽帧。

- 社区实现：`ltaoo/wx_channels_download`（`parse_sph`）、`yanlingLabs/video-extract-mcp`、
  `Evil0ctal/WeChat-Channels-Video-File-Decryption`（解密原理）。
- 代价：**要一份腾讯元宝/视频号的登录 Cookie**（会过期、要重贴）、多一个常驻进程、
  以及"微信一改就得跟"的长期维护。收益只有"偶尔转发的视频号"这一类。
- **为什么暂不做**：截至 2026-10-20，用户转发的链接里视频号只占 1/9，性价比不够；
  替代办法是让他录屏/截图发过来——笨鱼对任意视频都能抽帧。

### 给没字幕的视频加 ASR（2026-10-20 试过，先不做）

**为什么想要**：它自己在对话里的原话是「刚才那条 13 秒的视频没字幕，我直接瞎子」。
现在没字幕只能抽帧、靠画面猜，声音里讲了什么完全拿不到。`readBilibiliVideo` 的字幕路径
（`player/wbi/v2` 的字幕轨）对没有 CC 的视频是空的。

**已经试过的两条路（都堵死，别重复踩）**

1. **必剪 ASR 的 URL 直传**（`CZX2244/dsh-bilibili` 插件用的方式）：
   `POST /x/bcut/rubick-interface/task` + `{"resource": <音频URL>, "model_id": "8"}` 建任务能成功，
   但轮询永远 `state: 3`（失败）。**根因是 B 站音频有防盗链**：同一个 `dash.audio[0].baseUrl`，
   带 `Referer` 拉返回 **206**，不带返回 **403** —— 必剪的服务器去拉时没有 Referer，自然失败。
2. **先上传再转写**（必剪的 `resource/create` + `PUT upload_url`）：那个接口要必剪的**私有签名**，
   缺签名一律 `{"code":-400,"message":"请求错误"}`。参数怎么换都是 -400（试过 JSON / form /
   带 Referer / 带 content_type）。

> 结论：必剪这条路**没有中转服务器就走不通**。插件里也写着"best-effort，失败时由调用方降级"。

**唯一可行的路线：本地 ASR（不用服务器中转、免费、离线）**

```
readBilibiliVideo 拿不到字幕
  → playurl?fnval=16 取 dash.audio[0].baseUrl（带 Referer 能下，13 秒视频只有 98 KB）
  → 容器里 ffmpeg 转 16k 单声道
  → 本地引擎转写 → 当字幕用
  → 失败再降级回现在的抽帧
```

- 引擎选 **sherpa-onnx + SenseVoice**（中文强，模型 ~230 MB）；备选 whisper.cpp tiny（39 MB，中文差）。
- `Dockerfile` 要装二进制 + 模型（镜像会大 200~250 MB）。
- **必须用子进程**：转完就退出，不能常驻加载模型。

**资源账（2026-10-20 实测，清理后）**

- 磁盘：**25 G 可用**（够，模型才几百 MB）
- 内存：总 **1.8 G**，可用 **1069 MB**；SenseVoice 峰值约 400 MB，转写那几秒剩 ~650 MB，不会大量吃 swap
- CPU：**2 核**，转写会占满 1~2 核，那几秒 QQ 回复会变慢
- **swap 已用约 1 G**，说明这台机器本来就顶着跑；所以 ASR 只能是"进来干活、干完就走"的租客
- 想舒服点：升到 4 G 内存（阿里云升配要重启），但为了一个低频功能不一定值

**为什么搁置**：用户 2026-10-20 晚决定先不做（当天已经改了很多，且机器资源紧）。
