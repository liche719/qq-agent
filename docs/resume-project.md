## 一、项目概览（简历开头一行）

> **qq-agent｜独立开发并线上运营的 QQ 私聊 Agent**（Java 21 / Spring Boot 3.5 / PostgreSQL + pgvector / Redis / LangChain4j）
> 67 个工具、三层长期记忆、多轮任务闭环；单实例稳定运行，每日自动备份、一键回滚。

## 二、核心条目（挑 2~3 条放简历，其余留作面试展开）

### ① 分层记忆：让"他改主意了"能被正确处理

> 设计三层记忆：**原文证据层**（只追加、不可改写，用于防幻觉与审计）／**派生记忆层**（画像、经验）／**槽位事实层**（单值事实 + 取代链）。
> 事实带 `origin` 三级可信度（用户明说 / 模型推断 / 外部资料）与 `source_message_ids` 证据链：用户说"忘掉那次聊天"时，按证据级联把引用的事实标失效而不是删除。
> 写入侧两道去重：**提取阶段**按语义重复度（阈值 0.75）把重复内容放进 `duplicates` 不新增；**落库后**按向量相似度（0.92）判定近似重复，把新条标 `SUPERSEDED` 而不是并存。
> 实测依据：同一条经历被反复提取成 8 个措辞版本（相似度 0.953~0.987），检索时互相稀释，"上次那件事"因此排不进候选。

**可展开**：为什么分层（读写模式不同：原文只追加、事实必须互斥）；为什么"只能忘不能替"。

### ② 失败处理：把 LLM 的"错"当成预期事件

> 工具失败分三级：`TRANSIENT`（超时/5xx，代码层退避重试，不浪费一次模型调用）／`FIXABLE`（参数错，原样回传 Observation 让模型自己改）／`STRATEGIC`（连续失败或轮次过半，触发一次独立结构化反思 + 重规划，每轮上限 1 次）。
> 在此之上补三处：**同参重复检测**（同一工具 + 同一入参二次失败即强制重规划，防原地打转）、**单工具执行时限**（超时记为"结果未知"而非失败，避免重复副作用）、**副作用工具幂等键**（60 秒内同参直接返回上次结果；结果未知的 5 分钟内拦截重做）。
> 工具结果统一携带机器可读状态（`SUCCESS / FAILED / PARTIAL / UNKNOWN / NEEDS_INPUT`），模型按字段分支而不是靠中文标题猜。

**可展开**：为什么"结果未知"不能当失败重试（用户会收到两条一样的消息）。

### ③ 可评测、可观测：改版靠数据说话

> 自建评测体系并接入 CI 门禁：记忆 **28** 条用例（含别名召回、"改主意"后旧值不得残留）、Agent **19** 条（含任务级多轮：建提醒 → 读回存在 → 取消 → 校验落库为 0），每条重复 3 次取多数，避免小样本抖动。
> 生产侧有工具成功率/耗时、反思效果、单轮成本与缓存命中面板。
> 用数据驱动优化：例如定位到首字延迟主要花在"首跳思考档位"，下调后 **9.1s → 2.6s**。

**可展开**：为什么用"重复 3 次取多数"；任务级评测为什么必要（单轮"选对工具"的用例永远是绿的）。

### ④（可选）删除机制：负向决策也是能力

> 曾实现"按关键词动态裁剪工具集"：命中「考研/复习/计划/任务」等词就全量下发，否则摘掉 18 个考试工具。
> 实测发现它**几乎从不生效**（关键词表混入「计划」「任务」这类日常词，且"已有备考计划"直接短路），而收益不到单轮成本 3%（schema 本就在前缀缓存里），风险却是"误裁 → 模型说没有这个能力"。
> 最终删除该机制，改为**静态删除死工具 + 渐进式披露**（常驻 35/65，缺工具时用 `discoverTools` 按需解锁），既省 token 又不误裁。

### ⑤ 检索侧的"删功能"决策（2026-11-04 实测）

> 自建 250 题自动题库（从真实记忆反向生成问句、固定抽样），同一套题对比五种配置：

| 配置 | 召回率 | 平均注入字数 |
|---|---|---|
| 向量 + rerank | 53.6% | 1335 |
| 向量 + BM25 并集 + rerank | 52.8% | 2797 |
| 向量 + BM25 + RRF | 27.6% | 2298 |
| 向量 + BM25 并集 | 52.4% | 2772 |

> 结论：**RRF 在候选高度重叠时有害**（抹平语义，任务类召回掉到 15%）；**并集不是融合**（rerank 在更嘈杂的池子里挑，反而挤掉已命中的）；**rerank 成本不可持续**（3632 次调用烧光额度，每轮约 0.008 元）。
> 最终：删 rerank、关 BM25、删 RRF，把力气换到**指代型查询改写**（用最近 3 轮把"上次那件事"补成具体词，成本约为 rerank 的 1/40）。
> 未命中构成也印证了这点：**68% 是纯指代/情绪问题**（问题里没有任何可检索词），加召回通道无效。

**可展开**：为什么先做瓶颈分类再动手；为什么"看起来高级"的方案要先用数据验证。

## 三、面试预判问题与答法

| 追问 | 答法要点 |
|---|---|
| 为什么有了 RAG 还要 Memory？ | RAG 只读、面向公共知识；Memory 读写、面向这个用户。难点不是"存"而是**冲突消解**：他说"周三课改到 15:00"，旧值必须失效，否则同时召回两个时间 |
| 记忆为什么分层？ | 三层的**读写模式**不同：原文只追加（审计/防幻觉）、派生可重写但带来源和 TTL、槽位必须写时消解。分层是为了每层只解决一个问题 |
| 工具调不通怎么办？ | 三级分类 → 同参重复检测 → 超时归"未知" → 幂等键。一条链讲完 |
| 你怎么保证不重复发消息？ | 三处：`@NonIdempotentTool` 不自动重试、超时标记 `UNKNOWN`、Redis 幂等键（60s 成功去重 / 5min 未知拦截） |
| 你怎么知道效果变好了？ | 评测分数（28/28、19/19）+ 生产指标（工具失败率、首字延迟、缓存命中） |
| 你上过 rerank 吗？ | 上过，实测召回 53.6%，但成本 0.008 元/轮且 68% 的未命中是纯指代问题、精排无从下手——所以撤了，改做查询改写（成本 1/40） |
| 有没有踩过坑？ | 两个真事：① 一个工具因注解挂在私有方法上**从未注册**（生产一直是 64 个而非 65 个）；② 给工具加超时把执行挪进线程池，导致 ThreadLocal 用户上下文丢失，所有依赖上下文的工具报"上下文不可用"——**由任务级评测发现** |

## 四、写作注意事项

1. **别堆功能名**（"支持 xx、yy、zz"），写"在什么约束下做了什么取舍"。
2. **每个数字要么来自测量，要么不写**。现状可引用的实测值：
   - 工具 **65 个 / 21 个类**，常驻 **35/65**（渐进式披露）
   - 记忆评测 **28 条 100%**、Agent 评测 **19 条 100%**（含 1 条任务级）
   - 首字延迟 **9.1s → 2.6s**（首跳思考档位 high → medium）
   - 生产：`site=200`、0 ERROR、单轮对话预算上限 0.3 元
3. **主动暴露一处"没验证"的地方**（例如"被动回复分支的时序在真实流量下的分布还没统计"），面试官会认为你诚实且清楚边界。
4. 简历上每条控制在 **2 行以内**，细节留给面试展开。

## 五、可以补的三个"产品侧"短板（如果面试问"下一步做什么"）

1. **记忆的可见可控**：用户看不到"它记住了我什么"，只有 `/memory forget`。缺一个"我的记忆"列表 + 改/删入口。
2. **PII 落库打码**：记忆与备份里有手机号、地址明文，写入前应打码（保留后四位）。
3. **备份恢复演练**：备份每天生成且验证过完整性，但**恢复流程没有真跑过**——"能生成"和"能恢复"是两件事。
