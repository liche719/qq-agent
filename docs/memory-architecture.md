# 记忆系统：当前状态（唯一事实来源）

> 最后更新：2026-11-04
> 这份文档记录**现在实际在跑的**东西，不是设想。改之前先来核对这里。

## 1. 一句话

**写入保证不丢（去重 + 一件事一条），检索只做一次排序（向量），指代型问题先改写再查，其余交给时间验证。**

## 2. 检索链路（线上实际）

```
每轮对话
  ↓
MemorySignal 判意图（词表在配置 memory.signal.*）
  ├─ 寒暄/附和（≤8字 + 寒暄词 + 无疑问 + 无数字） → 只给画像（~50ms）
  └─ 其它
       ├─ MemoryQueryRewriter：指代型 → 用最近 3 轮改写成具体查询
       └─ 向量检索（pgvector）→ 装配（画像 + 任务 + 经历）
  ↓
注入提示词：STATE 摘要 + 最近 14 轮对话 + 记忆（约 1300 字）
  ↓
模型可主动调 recallMemory（67 个工具之一）做深挖
```

### 已关闭 / 已删除

| 组件 | 状态 | 原因（实测） |
|---|---|---|
| **rerank** | 代码已删 | 3632 次调用烧光额度；68% 未命中是纯指代问题，精排无从下手 |
| **BM25** | 代码保留，flag 关 | 250 题上并集后召回 52.8% vs 纯向量 53.6%，字数翻倍 |
| **RRF** | 已删 | 两路候选高度重叠，抹平语义，任务类召回掉到 15% |

## 3. 写入链路（线上实际）

```
对话 → conversation_memory（原文证据，永不改）
  ↓ 触发：≥15 轮（ROUNDS）或 ≥6 轮（BACKLOG，11-04 加）
MemoryExtractor（窗口 15 + 重叠 2 + 跳过 2）
  ↓
episodes / newWorkItems / coreCandidates / facts
  ↓ 规则：一件事一条、≤80 字（11-04 加）
MemoryService 落库 → 算向量 → 近似去重（>0.92 且更早的已存在 → 标 SUPERSEDED）
  ↓
写 STATE 摘要（覆盖更早的对话，每轮注入）
```

## 6. 已知风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **compose 不透传环境变量** | 今天踩 3 次：`.env` 改了容器里没有 | 改完必须 `docker exec printenv` 核对 |
| **验证工具会骗人** | `<set>` 掩码冒充值、`cut` 截断数字、stderr 混入 stdout | 提取数字用精确匹配，不截断关键行 |
| **指代型问题占 68%** | 没有可检索词，加通道无效 | 查询改写是唯一解法，效果待验证 |
| **提取积压** | 积压时 STATE 落后，而上下文只剩 14 轮 | 已加积压优先触发 |
| **无质量观测** | 召回只有离线题库（53.6%） | 建议打点：改写命中、recallMemory 调用 |
| **物理内存不足，走 swap** | 1870 MB 内存 + **Swap 已用 1492 MB**；同一台机器上还跑着 codeAireview（app/mq/pg/redis）。表现是**检索偶发慢**：正常 1 秒内，抖起来 3~21 秒，且每次慢的环节都不一样（画像 / 写使用时间 / 历史查询轮流慢） | 根治=升配到 4 GB；短期只能接受。**别把这类慢当成代码 bug 去优化** |
| **阿里云欠费会让向量检索静默失效** | 2026-11-04 实测：账号欠费 → embedding 返回 400 `Arrearage` → `EmbeddingClient` 打 WARN 后**按无向量处理**，记忆只剩画像。生图/TTS 用的是另一把 key，看不出异常 | 日志搜「取向量失败」；充值后自动恢复，无需重启 |

## 8. 工作纪律（今天踩出来的）

```
① 先写方案（改什么/为什么/预期/风险/怎么验证）→ 确认 → 再动手
② 改完先本地起一次，不直接上生产（logback 那次就是这么坏的）
③ 上线后核对容器内实际值，不看命令回显
④ 报告明确区分「已验证」和「没验证」
⑤ 一次只改一件事，改完立刻验证，再动下一件
```
