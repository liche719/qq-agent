# 上下文窗口、提取、STATE 的设计（2026-11-01 定稿）

> 这份文档回答：**一轮对话能看到什么、提取覆盖什么、STATE 是什么、什么情况下会漏**。
> 相关代码：`ConversationMemoryService`、`MemoryExtractor`、`AgentOrchestrator`、`MemoryService`。

## 1. 三个窗口，各管一件事

| | 作用 | 大小 | 数据来源 |
|---|---|---|---|
| **上下文窗口** | 模型这一轮能看到的原文 | 19 轮 | Redis（空了回落库） |
| **提取窗口** | 这次提取读哪些内容 | 19 轮 = 中间 15 + 前 2 + 后 2 | 库（从游标往后，最老优先） |
| **STATE** | 窗口之前的历史状态卡 | ≤400 字 | 由**事实 + 情景记忆 + 上一条 STATE** 合成 |

**关键**：STATE 不读原文，所以和上下文窗口零重叠。

## 2. 提取窗口怎么切（19 轮 → 15 轮）

```
R1  R2   [之后再提取]        ← 可能还没说完，下一轮再提
R3  … R17                    ← 真正提取（15 轮）
R18 R19  [背景/上次已处理]   ← 上次已提过，只当上下文
```

- 触发：待提取满 15 轮（`MEMORY_EXTRACTION_ROUNDS`）
- 兜底：最早一条放了 6 小时（`MEMORY_EXTRACTION_MAX_IDLE_HOURS`）
- **IDLE 兜底时不跳过后置两轮**（否则那两轮可能永远停在"之后再提取"）

## 3. STATE 的语义

```
每次提取（每 15 轮）：
  ① 19 轮原文 → 15 轮的事实（照旧）
  ② 这批事实 + 这批情景记忆 + 上一条 STATE → 新 STATE（≤400 字状态卡）
  ③ 光标推进到「实际喂进模型的最老一条之后」

每轮对话注入：
  ① <前情摘要>STATE</前情摘要>（写明截至时间）
  ② 最近 19 轮原文
  ③ 本轮消息 + 长期记忆块
```

**STATE 里写什么**：在做什么、卡在哪、已经定下来的事、下一步；**不罗列事实**（事实有事实层），**不复述原文**。
**为什么要带情景记忆**：事实是槽位化的单值信息，记不住"他最近很烦"——那类东西在 EXPERIENCE 里。

## 4. 什么时候会漏信息（唯一路径）

**积压超过单次窗口**：

```
两次提取之间新增 > 19 轮  →  最早那几轮被窗口滑过，永远提不到
```

实测参考：提取一次 30~50 秒。每秒 1 条消息时，一次提取期间就积压 25~50 轮 > 19。

**判定**：`pendingCount > 单次上限` 时记 WARN，面板显示"提取积压 N 轮"。

**修法**（已实现骨架）：
1. 窗口从"最近 38 行"改成"游标 → 现在"，**最老优先**；
2. 单次上限 60 行，超了分片，按顺序清空；
3. **游标按"实际喂进模型的最后一条 id"推进**——绝不能按时间戳或"当前最新一条"推进，否则期间新来的消息会被当成已处理。

## 5. 其他边界

| 情况 | 处理 |
|---|---|
| 没有 STATE | 注入里明确写「更早的对话没有摘要记录」，不让模型假装记得 |
| STATE 写入并发 | 只允许 `updatedAt` 更新的覆盖更旧的 |
| 提取失败 | 游标不动，下次重试；不会跳着丢 |
| Redis 空 | 回落到库，行为不变 |
| 字数上限 | `15000`；19 轮实测约 1.8 万字，实际可能只装 15~16 轮，需持续观察 |

## 7. 游标的两条硬规矩（2026-11-02 补）

### 7.1 首次没有游标时，从「现在」起步

实测教训：游标不存在时若默认 0，第一次提取会把**整个历史**当待处理——
日志 `提取积压 待处理=4374 行`，然后从几年前的旧对话开始提，提出来全是陈年旧事，
而且一次只能清 40 行，永远追不上。

**正确做法**：`cursor = latestId(userId)`，从最新一条开始，历史交给已有的记忆与事实。

### 7.2 写入 STATE 时用游标做单调保护

提取在后台跑，两次可能重叠。先启动的那次如果后完成，会把更新的 STATE 盖成旧内容。

**做法**：`memory.keywords` 里记 `cursor:<已处理到的消息 id>`；写入前比较：

```
本批 cursor <= 已有 cursor  → 丢弃这次写入（日志「丢弃过期的状态摘要写入」）
本批 cursor >  已有 cursor  → 正常写入
```

**只丢弃 STATE**，这一批的事实照常落库——状态卡落后可以下次补，事实不能丢。
