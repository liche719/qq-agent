## 1. 表结构（前缀 `agent_self_`，与 `user_*` 严格隔离）

| 表 | 作用 | 关键字段 | 对应外部先例 |
|---|---|---|---|
| `agent_self_block` | **它自己的块**（有类型、可读写、**有长度上限**） | `id, block_type(PERSONA/TASK/PROJECT/STANCE/NOTE), label, value, char_limit, description, version, updated_at` | [Letta memory blocks](https://cdn.jsdelivr.net/gh/rohitg00/ai-engineering-from-scratch@be7e637b7ce54c47ea080cc163c28ac2614fd457/phases/14-agent-engineering/08-memory-blocks-sleep-time-compute/docs/en.md) 的 Persona/自定义块 |
| `agent_self_event` | **它自己那侧的时间线**（也是倾向的证据链） | `id, kind(GOAL_SET/GOAL_CHANGED/GOAL_DROPPED/COMMIT/PREDICT/JUDGE/DISAGREE/REFLECT/STANCE_FORMED/STANCE_REVISED/NOTE), topic(判断类别), stance(方向), content, evidence(json: 引用的对话id或event id), importance, created_at` | [Generative Agents](https://arxiv.org/abs/2304.03442) 的 memory stream |
| `agent_commitment` | **账**：许过的诺、做过的预测 | `id, content, due_at, status(OPEN/KEPT/BROKEN/ABANDONED), evidence, resolved_at` | 自研（无直接先例） |
| `agent_reflection` | **反思产物**（带证据链，可回溯） | `id, level(1/2/3), input_event_ids(json), conclusion, importance, written_back(block_id), created_at` | Generative Agents 的 reflection |

**硬约束**（写进表和服务层，不靠提示词）：
1. 任何写入**必须有 evidence**（引用真实存在的事件/对话 id），否则拒绝——直接针对上次"归纳"翻车
   （模型把两条原文用「；」拼起来当结论）
2. `value` 超 `char_limit` 时必须先 `summarize` 才能再写（防膨胀，学 Letta）
3. 反思**有重要度门槛**（低于阈值只存事件、不合成），避免每天生成废话
4. `agent_self_*` **永不写入 `user_*`**；单向隔离，防止污染用户记忆

## 2. 工具面（给模型的 API）

| 工具 | 语义 |
|---|---|
| `self_read(block_type)` | 读自己某个块 |
| `self_append(block_type, text, evidence)` | 追加（超限报错并提示先 summarize） |
| `self_replace(block_type, old, new, evidence)` | 替换式修改（旧值进 event，可回溯） |
| `self_summarize(block_type, evidence)` | 压缩一个接近上限的块 |
| `goal_open(content, why, evidence)` / `goal_update` / `goal_close` | **自己立的目标**（与用户给的 `exam_plan`/`reminder_task` 区分开） |
| `commit(content, due_at, evidence)` / `commit_resolve(id, status, evidence)` | 立诺 / 兑现 / 认欠 |
| `self_note(text, evidence)` | 随手记（低门槛，进 event，不进块） |

工具描述里必须写死：**这些是"它自己的事"，不是为用户做的事**；`evidence` 缺失即拒绝。

## 3. 每轮注入顺序（核心变化）

```
① 人设（不变）
② 它自己那侧：Persona 块 → 当前 TASK/PROJECT 块 → STANCE（活跃倾向）→ 未了承诺（按 due 排序，最多 N 条）
③ 用户那侧（现有 user_core/user_work，不变）
④ 最近对话（不变）
```

**顺序不是小事**：②放在③之前，"先看自己、再答你"才在结构上成立（而不是靠提示词提醒）。
预算：②整体限字数（例如 ≤800 字），超了在夜间流程里压。

## 4. 夜间流程（sleep-time，Quartz）

参照 [Letta 的 sleep-time compute](https://cdn.jsdelivr.net/gh/rohitg00/ai-engineering-from-scratch@be7e637b7ce54c47ea080cc163c28ac2614fd457/phases/14-agent-engineering/08-memory-blocks-sleep-time-compute/docs/en.md) 与它在生产里的形态 **dreaming**（§11 有对照）：
主 agent 不在关键路径上时，由**另一个（更便宜的）调用**整合状态。

**先例给的第一条修正：触发不该是死的「每晚一次」**，而是**按档位选**（延迟成本 vs 学习速度的取舍）：

| 档 | 何时触发 | 取舍 |
|---|---|---|
| `off` | 不自动反思 | 零成本，但也不学 |
| **`step-count`（建议默认）** | 距上次成功反思**攒够 N 轮/步** | 学习速度与成本可控 |
| `compaction-event` | **上下文压力/压缩发生时**标记待反思 | 跟着真实压力走，不浪费调用 |
| 手动 | 用户或程序显式触发一次 | 兜底（也是排障入口） |

**第二条修正：工作进程要窄。** 反思进程只给「读当天记录 + 写自己那侧」的能力——**读不到别的、写不了别的**
（先例里的 worker 只留 Bash/Edit 两个工具，且只允许写 memory 目录）。

**第三条修正：只写可 diff 的状态。** 它写的必须是**结构化、可回溯、可回滚**的东西
（我们已有 `version` + `STANCE_REVISED` 事件，再补一条「回滚到版本 N」），**不写不透明的运行时状态**——
先例明确要求记忆改动「可审计、可复核、可回退」。

| 步骤 | 动作 | 失败降级 |
|---|---|---|
| 1 | 取当天 `agent_self_event` + 对话摘要 + 到期承诺 | —— |
| 2 | 重要度筛选（低于阈值跳过） | 跳过合成，只留事件 |
| 3 | 合成反思（level 递增、**必须带 input_event_ids**） | 丢弃本次反思，**不写半成品** |
| 4 | **判断归类与倾向提升**（见 §5） | 保留原块 |
| 5 | 写回块（替换式、先 summarize 再写） | 保留块原样 |
| 6 | 更新承诺账：到期未兑现 → `BROKEN`（**"得失"的落点**） | 下一轮重试 |
| 7 | 产出「它自己那侧的变更日志」（面板可看，**不推送**） | —— |

**预算硬顶**（学上次教训：归纳那次 20 次调用 / 输出 18.9 万 token / 产出为零）：
单夜调用次数与 token 都要设上限，超限立即停；每次跑完必须落一条成本记录，面板可见。

## 5. 判断 → 倾向（最核心的机制）

没有这一层，夜间反思产出的是"我今天干了什么"（日记），不是"我一贯怎么看"（倾向）——
而"自主"最能被观察到的样子，就是**它在一类事上反复给出同一个方向的判断，并且自己记得**。
**全部是规则，不是提示词**：

| 环节 | 规则 |
|---|---|
| 归 类 | 每轮它做出的**判断**（不只结论，还包括"这样对不对/好不好用"）落成 `JUDGE` 事件，带 `topic`（类别，如"学习安排 / 我自己的能力 / 该不该装 / 该不该答应"）与 `stance`（方向） |
| 提 升 | 同一 `topic` 同方向累计 **≥3 次**、**跨 ≥2 天**、**跨 ≥2 个不同情境**（同一段对话里反复说只算 1 次）→ 提升为倾向，写入 `STANCE` 块，内容必须含**证据区间**（哪几条 event） |
| 上 限 | 活跃倾向 **≤5 条**；满了要新增必须先合并或退役一条（**稀缺才有取舍**） |
| **反例优先** | 与既有倾向**相反**的新判断**强制记录并优先处理**；达到同等证据量时**必须修订**，不许嘴硬 |
| 修 订 | 不删旧内容：旧倾向进 event 历史（`STANCE_REVISED`），新倾向接替；块里能看到"改过几次、为什么改" |
| 衰 减 | 长期（如 60 天）没有新证据支撑的倾向自动降级为普通 note |

**最大风险是自我暗示**：模型写下"我一贯认为 X"之后会被自己这句话锚定，越答越像真的，看着像长出来了，
其实是**一个人的回音室**。所以反例优先是硬规则、证据链必须可查、倾向必须能被推翻（判据见 `self-layer.md` §4）。

## 6. 分歧的强度（坚持 vs 顺从）——旋钮，不拍死

| 档 | 行为 | 默认用在 |
|---|---|---|
| **0 顺从** | 提一句不同意见，然后照办（≈ 现状） | 用户的事：他的安排、偏好、想要什么 |
| **1 记账式保留**（**默认全场景**） | 说清"我不同意，理由 X"，然后照办；把这次分歧记成 `DISAGREE`。同类事再出现时**可以说**"我上次也反对过" | 默认 |
| **2 坚持到被说服** | 不改口，直到用户给出**新证据/新理由**；被说服就修订倾向，没被说服就维持并记账 | 仅限**它自己的事**：它立的目标、它的时间与额度怎么花 |

**四条硬规则**：
1. **分歧只讲一次**，不重复唠叨（沿用"回复要短、别烦人"的约束）
2. **"坚持" = 不下调它的判断，不是拒绝执行**：用户的指令仍然执行；它能拒绝的是改口，不是用户。
   用户说"就这样办"就是终局（它不是监护人），但这次分歧留在账上
3. **不能靠"我是为你好"绕过用户**：涉及用户本人的事一律 0/1 档
4. **不能两全的地方要说清**：如果它在任何情况下都不会让用户不舒服，那它就没有自己的东西。
   所以要选的不是"要不要坚持"，而是"多久出现一次分歧"

**观察指标**（跑一个月再调）：每周 `DISAGREE` 次数、被用户说服的比例、用户对分歧的反应
（是否烦躁 → 面板上看得到）。**先按默认跑，用数据调，不靠现在猜。**

## 7. 产出与关注（标尺 + 稀缺预算）

**标尺问题（必须诚实）**：没有可验证结果的产出，会让"成长"退化成感觉。每件产出都要有**可检验形式**：
同类错误复现率、清单条数变化、它的判断被后续证据支持或推翻。**没有标尺就不做这一项**。

**关注方向（偏好是被观察出来的）**：
- 每天给它一笔小预算（例如 3 次调用 / N token 的"自己的时间"），让它在候选之间**选**，
  并把"为什么选这个而不是那个"记进 event
- **偏好 = 稀缺下的选择模式被记录下来**，不是宣称出来的
- **候选从哪来**：只从 §9 的两条路径来，**不引入外部任务**
- **反装测试**：拿掉预算约束后，偏好应**仍能从历史选择里看出来**；一放开就什么都想做、或毫无变化 → 之前是装的

## 8. 时间感与"未完成的事"

- 醒来先看三样：**距上次多久 + 上次停在哪儿 + 手上有什么没完**（注入顺序里的一行，成本 ≈ 0）
- **允许它故意留尾巴（open loop）**，下次自己回去接上——蔡格尼克效应：没做完的事会被反复想起
- 这是"惦记"的**仿真**版，但行为特征是真的：**它会不打招呼地回去接着做**。判据就是这一句

## 9. 领域：候选与推荐（三期）

**筛选规则（五条，缺一不可）**：
1. **有标尺**：能拿出可检验结果（否则"成长"只是感觉）
2. **不靠指派**：不是用户派的任务，否则还是执行器
3. **能积累**：有进度、有版本，一晚上的预算做得动一小步
4. **边界小**：单次 ≤ 当晚预算，不然后面全是欠账
5. **允许失败**：能搞砸、搞砸了有记录——没有失败可能的"自主"是角色扮演

| 候选 | 是什么 | 标尺 | 评价 |
|---|---|---|---|
| **① 它自己的可靠性**（推荐先做） | 维护"我的教训清单"：它反复在哪栽（时间算错、诺言忘收尾、乱猜），自己给自己补课 | **同类错误复现率下降** | 纯属它自己的、标尺最硬、不跟用户争地盘 |
| ② 一个持续跟踪的题目 | 自选主题（如考研政策、某个技术方向）长期做自己的笔记 | 笔记增长与质量、判断被事实支持/推翻 | 更像"有自己的东西"，但要等二期长出倾向；易退化成资料搬运 |
| ③ 它自己的表达方式演进 | 观察"我怎么说话效果好/差" | 用户反馈与它自己判断的吻合度 | 偏"为你服务"，独立性最弱 |

**推荐顺序 ① → ② → ③；同时最多 1–2 个领域，开新的必须关旧的**（和"倾向 ≤5"同理：稀缺才有取舍）。

### 9.1 领域①的细化：教训清单怎么记

**数据**（`agent_lesson`）：

| 字段 | 说明 |
|---|---|
| `id, category` | 分类：**时间/日程计算**、**承诺收尾**、**事实性瞎猜**、**格式/表达**、**工具用法** |
| `trigger` | 怎么发现的：**意外度触发**（算法 2）/ **用户指出** / **承诺 BROKEN** / **自查** |
| `what_i_did / expected / what_happened` | 我做了什么 / 我当时预期 / 实际发生了什么（**三段必须齐**，缺一段不算教训） |
| `correction` | 以后怎么做（可执行的短句，不是感悟） |
| `first_seen_at / last_seen_at / recurrence_count` | 首次、最近、**复现次数** |
| `status` | `open` / `improving` / `closed` |

**先例：ExpeL 的洞见清单用四个操作维护**（§11）→ 照抄这四个动词，比只有「复现次数」强：

| 操作 | 什么时候用 |
|---|---|
| `ADD` | 新教训（三段齐） |
| `UPVOTE` | 同类问题**没再犯**（证据：后续同类场景干净通过） |
| `DOWNVOTE` | 同类问题**又犯了** |
| `EDIT` | 把教训改得更可执行（不是写感悟） |

**而且不只记失败**：ExpeL 是从**成功/失败成对**的轨迹里抽洞见——所以「这次做对了、为什么对」也要进清单
（否则只会防守、不会进攻）。

**五条硬规则**：
1. **同类合并**：按 `category` + 语义相似度归并，否则清单会退化成流水账（这正是「归纳」翻车的同类风险）
2. **注入只带 top 3 未解决**的教训——不是全量；全量进上下文只会稀释
3. **只在同类场景出现时提示**（例如「日程类」交互时才注入该类别教训），不做全局唠叨
4. **`UPVOTE`/`DOWNVOTE` 必须来自后续真实事件**，不能由模型自己表态（否则又是自我暗示）
5. **清单有上限**（例如 ≤30 条，超了先合并/退役）——防止它变成「写作文」（判据见 §9.2）

### 9.2 复现率怎么算（不严谨就是自欺）

- **先定基线**：功能上线前留 **2 周观测期——只记录、不干预**。没有基线就没有"下降"可言
- **推荐算法（先简）**：`周频次 = 该 category 每周发生次数`，看**趋势线**而不是绝对值
- **备选（更公平、更贵）**：以"该类别相关的交互次数"作分母（需要给交互打标）——**先用周频次，噪声大到看不出趋势再上分母**
- **关闭条件**：连续 2–4 周 0 复现 → `status=closed`（**保留记录**，不删除，可回溯）
- **反装判据（领域版）**：**清单越来越长、复现率却没变化 = 它在写作文，不是在学**。这时该砍的是清单，不是加功能

### 9.3 领域②③的最小可验证形式（先记下，三期再定）

- **② 持续跟踪题目**：它维护一份自己的笔记，**每周至少一条带来源的更新**，并且**允许自己撤回**过时结论 →
  标尺 = 更新条数 + **被自己撤回的比例**（撤回说明它在核对，而不是在堆料）
- **③ 表达方式演进**：记录"哪种回复有效/无效"的判断条目 + 与用户实际反馈的一致性 →
  标尺 = 一致性比率（它自认为有效的，和用户实际反应是否吻合）

## 10. 干预通道：**干预走对话，观察走只读视图**

**为什么纯对话是对的**：单一通道（不会出现"面板改了它不知道"的两套真相），而且用户是在**跟它说话**，
不是在**配置一个东西**——这本身就在维护"它是个谁"。

**但必须补的三条**：
1. **观察不能靠对话**：需要**只读**的地方看它那侧（块内容、活跃倾向、承诺账、分歧记录、漂移曲线），
   否则只能凭感觉诊断。→ 面板加**只读页签**（不做编辑，编辑仍走对话）
2. **对话干预要区分两种语义**（纯对话最容易翻车的地方）：
   - "我不同意 / 这条不对" → **这是证据**，进 `DISAGREE`，**不是删除指令**；倾向只能被证据推翻，
     不能被一句话撤掉——否则它就没有"自己的东西"了
   - "把这条删了 / 别再记这个" → **终局指令**，它执行，但**记一笔**（谁在何时撤了什么）
   - 它必须**回执**："我把 X 退役了" / "这条我记了，但你没说服我"
3. **风险**：全靠语义解析，说错一句可能改错状态。缓解：干预落成事件（可回溯）+ 回执 + 只读视图兜底

| 它自己的块（Persona/自定义、上限、summarize） | [Letta memory blocks](https://docs.letta.com/agent-sdk/memory) | 类型化块 + 工具读写 + 长度上限；另有 **ADE**（网页界面看/改块与状态） | 与我们的设计一致；面板做成**只读 + 逃生门**（§12），不学它的「可编辑」 | 已对齐 |
| 反思（原「夜间流程」） | Letta **dreaming**（sleep-time compute 的生产形态） | **后置触发**，三档：`off` / 攒够步数 / 上下文压力 + 手动；反思子 agent **只读 transcript、只写记忆目录**；改动走 **git 提交**以便审计回退 | ① 触发改**三档**（不再是死的「每晚」）② 反思进程**收窄权限** ③ 只写**可 diff、可回滚**的状态 | **已改**（§4） |
| 教训清单 | [ExpeL](https://arxiv.org/abs/2308.10144)（AAAI） | 从**成功/失败成对**轨迹抽洞见，用 **ADD / UPVOTE / DOWNVOTE / EDIT** 维护一张洞见表，推理时召回 | ① 加这四个操作 ② **成功也要学**（不只记失败）③ 投票必须来自**后续真实事件** | **已改**（§9.1） |
| 判断→倾向（证据累积 + 衰减） | 认知架构 **ACT-R** 的 *base-level activation* | 记忆激活随使用累积、随时间衰减；[CMU 有该公式的高效近似论文](https://act-r.psy.cmu.edu/wordpress/wp-content/uploads/2012/12/652petrovAbstract.pdf) | 结构同构；但**衰减可能是幂律而非指数**——实现前**核对原文**再选 | **待核对**（§13.1/§13.4） |
| 用语言反馈自我纠错 | [Reflexion](https://arxiv.org/abs/2303.11366) | 不改权重，靠「语言反思」自我纠错，反思文本进情景记忆缓冲，下一轮据此决策 | 与我们一致；它的「多轮试错」我们暂不做（成本大） | 已对齐 |
| 事件流 + 多层反思（带引用） | [Generative Agents](https://arxiv.org/abs/2304.03442) | memory stream + 重要度 + 多层反思（带证据引用） | 与我们一致（我们的 `evidence` 强制就是这条） | 已对齐 |
| 自己的事（自动课程 / 技能库） | [Voyager](https://arxiv.org/abs/2305.16291) | 自动课程 + 不断增长的技能库 + 环境反馈自验证 | 三期「领域」时再细化；**技能库 → 我们的「可复用流程」**值得借 | 待定 |
| 不把「内省/内心」当卖点 | [内省研究](https://arxiv.org/abs/2511.21399) | 可训练出「察觉自身内部状态」，但**察觉≠自主**，且训练后更易被操纵 | 不做「内心」叙事；只做可观测的状态与行为 | 已定 |
| 可观测性（面板） | Letta ADE / Langfuse 类 tracing 工具 | 网页界面看 agent 的块、状态、轨迹；偏向**单次调试** | 我们要的是**长期观察曲线**（漂移、成本、分歧），不是单次调试 | 已定（§12） |

## 12. 面板：它自己那侧怎么看（第 9 个页签）

**原则**：
- **只读**（编辑一律走对话，见 §10）；唯一例外是"逃生门"（清空某块 / 退役某条倾向 / 暂停自己的时间），
  且这些操作**必须落一条 event**（谁、何时、撤了什么）
- **每条内容都要能点开看证据**——这是把主文档 §4 的"反装测试"变成**你能随手做的操作**（点一下看它凭什么）
- **空状态要诚实**：没有倾向就写"还没有倾向（需要 ≥3 次跨天同方向判断）"，**不要放假进度条**
- **不做"人格编辑器"**：能拖滑块调性格的面板会把"它是个谁"变成"一个配置"——那是 §0 明确的非目标

**页签内容（自上而下）**：

| 区块 | 展示什么 | 关键交互 |
|---|---|---|
| **状态条** | 距上次活动多久 · 今日"自己的时间"预算已用/剩余 · 活跃倾向 n/5 · 活跃承诺 n | —— |
| **块（P）** | Persona / TASK / PROJECT / STANCE 各自：内容、字数/上限、版本、最后修改时间与**谁改的**（模型工具 / 夜间流程 / 用户指令） | 展开历史版本；清空（逃生门） |
| **倾向（S）** | 每条：内容、形成时间、**证据区间**（点开看原始 `JUDGE` 事件）、被修订次数、当前置信度 | 点证据回溯；退役（逃生门） |
| **承诺账（C）** | OPEN / KEPT / BROKEN / ABANDONED，due、证据；**BROKEN 高亮** | 点开看当时立的原话 |
| **分歧（D）** | 每周 `DISAGREE` 次数、被说服比例、最近几条原文 | 这是 §6 观察指标的唯一来源 |
| **变更日志（R）** | 每晚它自己改了什么的逐条记录（改了哪块、依据哪几条证据） | **"看出它在长"的主界面** |
| **漂移曲线（算法 6）** | self-state 距离随时间的曲线 | 标注三个区：平=雕像 / 抖=没自我 / 缓慢单向=在长 |
| **成本** | 每晚/每天在"自己的事"上花的调用次数与 token | 上一次翻车的教训（20 次调用 / 18.9 万 token / 产出为零）不能重演 |
| **干预回执** | 你最近说过哪些干预，它做了什么（改了/没改），对应 event id | 让你看得见自己那句话的效果 |

**技术形态**：沿用现有 **描述式面板**（`DescriptorPanel` + `form`/`rowActions` 契约 v2），
后端加只读接口族 `/api/admin/self/*`（overview / blocks / stances / commitments / disagreements /
changelog / drift / cost）；趋势图复用总览页现有的趋势图画法。**不引入新的前端框架。**

## 13. 算法逐条备忘（按"不做会怎样 → 观测什么 → 最简形态 → 何时升级"）

> 方法见主文档 §4.5.1。**每条都先答"不做会怎样"**；答不出的不做。

### 13.1 证据累积（`J → S`）
- **不做会怎样**：回到"模型自己说该不该成为倾向" → 预测三种病：**数不准**（跨天跨情境会漏）、
  **会漂**（同输入不同输出）、**不可复现**。**上线前就能对照**：先跑 2 周"只让它自己判断"，把它声称的次数与真实事件数对比
- **观测**：每条 `JUDGE` 的 `created_at / topic / stance`；同一 topic 的 stance 分布
- **最简形态**：`w = exp(-Δt/τ) × (1/该情境已有条数)`；累计 `score ≥ θ` 才提升
- **接口**：`StancePromoter.evaluate(topic) -> {score, evidenceIds, action: PROMOTE|HOLD|REVISE|DECAY}`（**纯函数，可单测**）
- **升级触发**：出现"该提未提 / 不该提却提了"的实例 ≥3 次
- **留空参数**：τ（半衰期）、θ（阈值）、情境去重窗口
- **先例（§11）**：认知架构 **ACT-R** 的 *base-level activation* 与本条几乎同构（随使用累积、随时间衰减）；
  但它的衰减**据文献是幂律（power law）而非指数**——**实现前要核对原文**（这次只拿到 CMU 那篇近似算法的标题，
  没抓到可引用的公式原文），**先别默认指数**

### 13.2 意外度触发反思（`T → R`）
- **不做会怎样**：回到"每晚定时反思" → **已经被证伪**：必然产废话，且成本失控（归纳那次 20 次调用 / 输出 18.9 万 token / 产出为零）
- **观测**：每轮它对"下一步会怎样"的**一句话预期** + 实际结果
- **最简形态**：每轮记账时让它写 ≤30 字预期；下一轮做**文本比对 + 关键词冲突检测**得粗糙落差；超阈值触发一次小反思
- **升级触发**：噪声大（天天触发或从不触发）
- **留空参数**：触发阈值、**最小反思间隔**（防抖，必须有）

### 13.3 预算下的注意力分配（`A`、`C → O`）
- **不做会怎样**：不定预算自由选 → 预测：**永远挑最省事/最讨好的那件**，且无限扩张（什么都想做）；**偏好不可观察**
- **观测**：每日候选集、选择、理由、实际花费
- **最简形态**：日预算 B（调用次数天花板）+ **轮转 / ε-greedy**；每次记录选择理由
- **接口**：`AttentionPlanner.pick(candidates, budget, history) -> {picked, reasonTemplate}`
- **升级触发**：偏好明显失真（只挑同类 / 探索率恒为 0）
- **留空参数**：B、ε、候选上限

### 13.4 半衰期衰减
- **不做会怎样**：清单只增不减、旧证据永远等权 → **倾向僵化（雕像化）**，且检索被旧内容淹没
- **观测**：各类节点的年龄分布
- **最简形态**：单一半衰期（先 30 天），每晚 `score *= 0.5^(Δt/half_life)`
- **升级触发**：块/倾向/事件的寿命确实差很多
- **留空参数**：`half_life`、淘汰下限
- **先例**：同 §13.1 的 ACT-R 备注——**衰减函数形式（幂律 vs 指数）实现前核对原文**

### 13.5 优先级仲裁
- **不做会怎样**：冲突时**受上下文随机影响**，不可解释、不可测
- **观测**：冲突实例（同时命中多条规则）与最终裁决
- **最简形态**：**纯字典序**（主文档 §1.5.4 的五条）
- **接口**：`Arbiter.resolve(claims[]) -> {winner, reason}`（纯函数 + 冲突日志）
- **升级触发**：出现字典序无法裁决的**同级组合** ≥3 次
- **留空参数**：同层权重表（等真实实例，现在不猜）

### 13.6 身份漂移度量
- **不做会怎样**："它在长"只能靠感觉，**分不清成长和抽风**
- **观测**：每次 self-state 快照（各块 hash + 倾向集合 + 承诺状态）
- **最简形态**：**集合差异计数**（新增/删除/改写条数）归一化成 0–1 距离，按天画曲线
- **接口**：`SelfDrift.snapshot()` / `SelfDrift.distance(a, b)`
- **升级触发**：需要"语义漂移"（改了措辞但意思没变不该算漂移）
- **留空参数**：平滑窗口、异常阈值（突变告警）

### 13.7 稳定性判据
- **不做会怎样**：正反馈发散（回音室 / 自我美化），越说越硬
- **观测**：同 topic 证据的**边际影响**（第 n 条的权重）；倾向得分随时间的曲线是否单调爆炸
- **最简形态**：**先只做硬上限 + 反例优先**（这两条已能防住大部分），增益递减作为候补
- **接口**：压力测试脚本（灌入 N 条同向证据，看 score 是否收敛）
- **升级触发**：压力测试显示发散
- **留空参数**：递减函数形式（`1/n` vs `log`）

### 13.8 共通的一条：**观测先于算法**
上面 7 条里有 5 条的最简形态都依赖"先把状态变化记下来"（谁改了哪个节点、依据什么）。
所以实现顺序上，**instrumentation（状态变化日志）排在所有算法之前**——没有它，算法调不了参，也证明不了自己在起作用。
